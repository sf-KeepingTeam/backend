```
현재 구조:
┌─────────────────────────────────────┐
│              EC2                     │
│   ┌─────────────────────────────┐   │
│   │         Docker              │   │
│   │   ┌─────────────────────┐   │   │
│   │   │       MySQL         │   │   │  ← 모든 데이터가 여기
```

### 대안 1: EBS 스냅샷 (우리의 선택 ✅)

```
┌─────────────┐         ┌─────────────┐
│    EC2      │         │     S3      │
│   ┌─────┐   │  스냅샷  │  ┌───────┐  │
│   │ EBS │───┼────────→│  │백업   │  │
│   │볼륨 │   │  (자동)  │  │데이터 │  │
│   └─────┘   │         │  └───────┘  │
└─────────────┘         └─────────────┘
```

**장점:**
- 저렴 ($2~4/월)
- 설정 간단 (5분)
- EC2 전체 복구 가능 (OS + DB + 앱)
- AWS 관리형 (자동)

**단점:**
- 복구 시 EC2 재시작 필요
- 실시간 복제 아님

**선택 이유:** 학습/포트폴리오 프로젝트에 최적. 비용 대비 효과 최고.

### 대안 2: MySQL 덤프 + S3 업로드

```
┌─────────────┐         ┌─────────────┐
│    EC2      │         │     S3      │
│   ┌─────┐   │ mysqldump│  ┌───────┐  │
│   │MySQL│───┼────────→│  │.sql   │  │
│   └─────┘   │  (cron)  │  │파일   │  │
└─────────────┘         └─────────────┘
```

**설정 방법:**
```bash
# backup.sh
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
docker exec mysql mysqldump -u root -p$PASSWORD keeping > backup_$DATE.sql
aws s3 cp backup_$DATE.sql s3://my-bucket/backups/
rm backup_$DATE.sql

# crontab (매일 새벽 3시)
0 3 * * * /home/ec2-user/backup.sh
```

**장점:**
- 매우 저렴 ($1~2/월)
- DB 데이터만 백업 (용량 작음)
- 특정 테이블만 복구 가능

**단점:**
- 스크립트 직접 작성 필요
- 복구 시 수동 작업 필요
- OS/앱 설정은 백업 안 됨

## 1. EBS란?

### Elastic Block Store (EBS)

```
┌─────────────────────────────────────────────────────────┐
│                       EC2 인스턴스                       │
│   ┌─────────────────────────────────────────────────┐   │
│   │                    운영체제                      │   │
│   │                    애플리케이션                  │   │
│   │                    Docker                       │   │
│   └─────────────────────────────────────────────────┘   │
│                          │                              │
│                          │ 읽기/쓰기                    │
│                          ▼                              │
│   ┌─────────────────────────────────────────────────┐   │
│   │              EBS 볼륨 (가상 하드디스크)          │   │
│   │                                                  │   │
│   │   /dev/xvda (루트 볼륨)                         │   │
│   │   - 운영체제 파일                               │   │
│   │   - Docker 데이터                               │   │
│   │   - MySQL 데이터 (Docker Volume)                │   │
│   │   - 애플리케이션 로그                           │   │
│   │                                                  │   │
│   │   용량: 8GB ~ 16TB                              │   │
│   └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 특징

| 특징 | 설명 |
|------|------|
| 네트워크 연결 | EC2와 네트워크로 연결된 별도 스토리지 |
| 영속성 | EC2 종료해도 데이터 유지 |
| 가용영역 | 특정 AZ에 존재 (ap-northeast-2a 등) |
| 스냅샷 | S3에 백업 가능 |

## 2. 스냅샷이란?

### 정의

```
스냅샷 = EBS 볼륨의 특정 시점 복사본

┌──────────────┐                    ┌──────────────┐
│  EBS 볼륨    │      스냅샷        │     S3       │
│              │  ─────────────→    │  (백업 저장) │
│  현재 상태   │     생성           │              │
│  - OS        │                    │  스냅샷 #1   │
│  - MySQL     │                    │  스냅샷 #2   │
│  - Docker    │                    │  스냅샷 #3   │
└──────────────┘                    └──────────────┘
```

### 스냅샷으로 할 수 있는 것

1. **복구**: 과거 시점으로 데이터 되돌리기
2. **복제**: 다른 EC2에 같은 데이터 복사
3. **이전**: 다른 리전/AZ로 데이터 이동
4. **AMI 생성**: 스냅샷으로 EC2 이미지 생성

## 3. 스냅샷 동작 원리

### 3.1 증분 백업 (Incremental Backup)

```
┌─────────────────────────────────────────────────────────────────┐
│  첫 번째 스냅샷: 전체 데이터 저장                                │
│                                                                  │
│  EBS (20GB)                         스냅샷 #1                   │
│  ┌─────────────────────┐            ┌─────────────────────┐     │
│  │ ████████████████████│  ────→     │ ████████████████████│     │
│  │ ████████████████████│            │ ████████████████████│     │
│  └─────────────────────┘            └─────────────────────┘     │
│        20GB 전체                         20GB 저장              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  두 번째 스냅샷: 변경된 부분만 저장                              │
│                                                                  │
│  EBS (20GB)                         스냅샷 #2                   │
│  ┌─────────────────────┐            ┌─────────────────────┐     │
│  │ ████████████████████│            │                     │     │
│  │ ████████░░░░████████│  ────→     │ ░░░░                │     │
│  └─────────────────────┘            └─────────────────────┘     │
│     ↑ 변경된 부분                       500MB만 저장           │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  세 번째 스냅샷: 또 변경된 부분만 저장                           │
│                                                                  │
│  EBS (20GB)                         스냅샷 #3                   │
│  ┌─────────────────────┐            ┌─────────────────────┐     │
│  │ ████████████████████│            │                     │     │
│  │ ██░░████████████████│  ────→     │ ░░                  │     │
│  └─────────────────────┘            └─────────────────────┘     │
│     ↑ 변경된 부분                       200MB만 저장           │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 스냅샷 체인

```
복구 시 스냅샷들을 조합해서 완전한 데이터 생성:

스냅샷 #1 (전체)  +  스냅샷 #2 (변경분)  +  스냅샷 #3 (변경분)
     ↓                    ↓                     ↓
    기본 데이터     +    변경 내용 1      +    변경 내용 2
                              ↓
                    완전한 20GB 데이터 복원
```

### 3.3 보관 정책

```
7일 보관 정책 예시:

Day 1:  [S1]
Day 2:  [S1] [S2]
Day 3:  [S1] [S2] [S3]
Day 4:  [S1] [S2] [S3] [S4]
Day 5:  [S1] [S2] [S3] [S4] [S5]
Day 6:  [S1] [S2] [S3] [S4] [S5] [S6]
Day 7:  [S1] [S2] [S3] [S4] [S5] [S6] [S7]  ← 7개 유지
Day 8:  [S2] [S3] [S4] [S5] [S6] [S7] [S8]  ← S1 삭제, S8 추가
Day 9:  [S3] [S4] [S5] [S6] [S7] [S8] [S9]  ← S2 삭제, S9 추가
  ...

→ 항상 최근 7일간의 스냅샷 유지
→ 8일 전 데이터는 복구 불가
```

## 4. 스냅샷 설정 방법

### 4.1 수동 스냅샷 생성

```
AWS 콘솔 → EC2 → Elastic Block Store → 볼륨
→ 볼륨 선택 → 작업 → 스냅샷 생성
```

### 4.2 자동 스냅샷 (Data Lifecycle Manager) - 권장

#### Step 1: DLM 정책 생성

```
AWS 콘솔
  → EC2
  → Elastic Block Store
  → 수명 주기 관리자 (Lifecycle Manager)
  → 수명 주기 정책 생성
```

#### Step 2: 정책 설정

```yaml
정책 유형: EBS 스냅샷 정책

대상 리소스:
  리소스 유형: 볼륨
  대상 태그:
    Key: Backup
    Value: true    # 이 태그가 있는 볼륨만 백업

일정:
  이름: DailyBackup
  빈도: 24시간마다
  시작 시간: 09:00 UTC (한국 18:00)

보존:
  보존 유형: 개수
  보존 개수: 7    # 최근 7개 유지
```

#### Step 3: EC2 볼륨에 태그 추가

```
EC2 → Elastic Block Store → 볼륨 → 볼륨 선택 → 태그
  → 태그 추가:
    Key: Backup
    Value: true
```

### 4.3 AWS CLI로 설정

```bash
# 수동 스냅샷 생성
aws ec2 create-snapshot \
  --volume-id vol-1234567890abcdef0 \
  --description "Manual backup 2026-03-19"

# 스냅샷 목록 조회
aws ec2 describe-snapshots \
  --owner-ids self \
  --query 'Snapshots[*].[SnapshotId,StartTime,Description]'
```

## 5. 복구 방법

### 5.1 시나리오: 데이터 손상 복구

```
문제: MySQL 데이터가 손상됨
목표: 어제 스냅샷으로 복구

┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  손상된 EC2  │     │   스냅샷     │     │   새 EC2     │
│              │     │  (어제 것)   │     │              │
│  ┌────────┐  │     │              │     │  ┌────────┐  │
│  │ 손상DB │  │     │              │ ──→ │  │ 정상DB │  │
│  └────────┘  │     │              │     │  └────────┘  │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 5.2 복구 방법 A: 새 볼륨 생성 후 교체

```bash
# Step 1: 스냅샷에서 새 볼륨 생성
AWS 콘솔 → EC2 → 스냅샷 → 스냅샷 선택 → 작업 → 볼륨 생성

# Step 2: EC2 중지
AWS 콘솔 → EC2 → 인스턴스 → 인스턴스 중지

# Step 3: 기존 볼륨 분리
AWS 콘솔 → EC2 → 볼륨 → 기존 볼륨 → 작업 → 볼륨 분리

# Step 4: 새 볼륨 연결
AWS 콘솔 → EC2 → 볼륨 → 새 볼륨 → 작업 → 볼륨 연결
  → 디바이스: /dev/xvda (루트 볼륨인 경우)

# Step 5: EC2 시작
AWS 콘솔 → EC2 → 인스턴스 → 인스턴스 시작
```

### 5.3 복구 방법 B: 스냅샷으로 새 EC2 생성

```bash
# Step 1: 스냅샷에서 AMI 생성
AWS 콘솔 → EC2 → 스냅샷 → 스냅샷 선택 → 작업 → 이미지 생성

# Step 2: AMI로 새 EC2 시작
AWS 콘솔 → EC2 → AMI → AMI 선택 → 시작하기

# Step 3: 탄력적 IP 재연결 (필요시)
AWS 콘솔 → EC2 → 탄력적 IP → IP 선택 → 연결
```

### 5.4 복구 예상 시간

| 볼륨 크기 | 스냅샷 생성 | 복구 시간 |
|----------|------------|----------|
| 8GB | 2-5분 | 5-10분 |
| 30GB | 5-10분 | 10-20분 |
| 100GB | 10-20분 | 20-40분 |

## 6. 비용

### 6.1 스냅샷 비용 계산

```
서울 리전 (ap-northeast-2) 기준:
$0.05 / GB-월

예시 계산:
- 첫 스냅샷: 20GB (전체)
- 이후 스냅샷: 각 500MB (변경분)

7일 보관 시:
  20GB + (0.5GB × 6) = 23GB
  23GB × $0.05 = $1.15/월

30일 보관 시:
  20GB + (0.5GB × 29) = 34.5GB
  34.5GB × $0.05 = $1.73/월
```

### 6.2 비용 예시표
