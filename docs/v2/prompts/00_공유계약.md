# 공유 계약 — v2 작업 1·2 (모든 도메인AI 공통)

> **실행 모드: 무인.** 사람이 자리에 없다. 모든 에이전트는 **코드 파일만 수정하고 아무것도 실행하지 않는다.**
> `./gradlew`, `docker`, DB 접속, `git` 쓰기, `gh`, `curl`, 패키지 설치, 서버 실행 전부 금지.
> 커밋·브랜치·PR을 만들지 않는다. 아래 "PR #NN"은 **변경세트 번호**로 읽는다.
> 상세는 각 도메인AI 프롬프트의 §0을 보라.
>
> 이 문서는 **오케스트레이션AI가 소유**한다. 도메인AI는 읽기만 하고 **임의로 바꾸지 않는다.**
> 변경이 필요하면 도메인AI는 작업을 멈추고 오케스트레이션AI에게 변경 제안을 보고한다.
> 각 도메인AI 프롬프트에는 이 내용이 §3으로 복사되어 들어간다. 원본은 이 파일이다.

## C-1. 불변식 (모든 판단의 기준)

```
목표 불변식:  SUM(wallet_store_lot.amount_remaining WHERE lot_status='ACTIVE')
              == wallet_store_balances.balance          -- (wallet_id, store_id) 단위
```

- **lot이 원장(정답)이고 balance는 파생값이다.** 둘이 다르면 lot을 믿는다.
- 만료 정산 시 `amount_remaining`을 0으로 만들기 때문에 **시간 술어(`expired_at > now`)가 불변식에서 사라진다.** 이게 이 설계의 핵심 이득이다. 대사가 시계에 의존하지 않게 된다.
- 새 write 경로를 추가하는 사람은 **balance와 lot을 같은 트랜잭션에서 짝으로** 갱신해야 한다. 예외 없음.

## C-2. 락 순서 (위반하면 데드락)

```
balance 행 락  →  lot 행 락       ← 저장소 전체 규약. 절대 역순 금지
```

기존 코드가 전부 이 순서다: `InternalWalletService.capture`(balance FOR UPDATE → lot UPDATE), `PaymentRefundService`(`findByWalletAndStoreForUpdate` → `findAllByTransactionIdWithLotLock`), `WalletService.sharePoints/reclaimPoints`(balance 락 → `lockAllByWalletIdAndStoreIdOrderByAcquiredAt`).

새로 만드는 만료 배치·대사 배치도 이 순서를 지킨다.

## C-3. DDL (schema-agent 소유 — 다른 도메인AI는 실행하지 않는다)

```sql
ALTER TABLE wallet_store_lot
  ADD COLUMN expired_settled_at DATETIME(3)     NULL COMMENT '만료분을 balance에서 차감한 시각(멱등 마커)',
  ADD COLUMN expired_amount     BIGINT UNSIGNED NULL COMMENT '만료 시점 잔량(소멸액)',
  ADD KEY idx_lot_expiry_sweep (expired_settled_at, expired_at, lot_id);
```

JPA 매핑 이름(wallet-agent가 `WalletStoreLot`에 추가):

| 컬럼 | 필드 | 타입 |
|---|---|---|
| `expired_settled_at` | `expiredSettledAt` | `LocalDateTime` (nullable) |
| `expired_amount` | `expiredAmount` | `Long` (nullable) |

**`LotStatus` enum은 건드리지 않는다.** `EXPIRED`를 추가하지 않는다 — 근거는 설계안 §3-1.
**`TransactionType` enum도 건드리지 않는다.** 만료는 `transactions` 행을 만들지 않는다.

## C-4. 신설 클래스 시그니처 (wallet-agent 소유 — 다른 도메인AI는 이대로 호출만 한다)

패키지: `com.ssafy.keeping.domain.wallet.service`

```java
@Service
@RequiredArgsConstructor
public class WalletLedgerService {

  /**
   * 원거래의 USE move(delta<0)를 근거로 lot을 복원하고 복원 move(+)를 기록한다.
   * 호출자는 이미 해당 (wallet, store)의 balance 행 락을 쥐고 있어야 한다. (C-2)
   * 상한 초과(remaining+restore > total) 시 CustomException(FUNDS_INVARIANT_VIOLATION).
   * @return 복원 총액
   */
  long restoreLotsByOriginalTx(Transaction original, Transaction cancelTx);

  /**
   * (wallet, store)의 미정산 만료 lot을 정산한다.
   * lot: amount_remaining → 0, expired_amount = 이전 잔량, expired_settled_at = now
   * balance: min(balance, 만료합계) 만큼 차감 (클램프. 부족분은 mismatch 카운터 + 로그)
   * 호출자는 이미 balance 행 락을 쥐고 있어야 한다. lockedBalance로 그걸 강제한다.
   * @return balance에서 실제 차감한 금액
   */
  long settleExpiredLots(Long walletId, Long storeId, LocalDateTime now,
                         WalletStoreBalance lockedBalance);

  /** (wallet, store)의 ACTIVE lot 잔량 합계. 대사·검증용. 락 없음. */
  long sumActiveLotRemaining(Long walletId, Long storeId);
}
```

## C-5. 메트릭 (platform-agent 소유 — 상수 클래스로 제공. 문자열 하드코딩 금지)

`com.ssafy.keeping.global.metrics.LedgerMetrics` 에 상수와 헬퍼를 둔다.

| 이름 | 타입 | 태그 | 의미 |
|---|---|---|---|
| `wallet_ledger_mismatch_total` | Counter | `cause` = `lot_shortfall` \| `expiry_clamp` \| `reconcile` | 불변식 위반 감지 |
| `wallet_lot_expired_total` | Counter | – | 만료 정산된 lot 건수 |
| `wallet_lot_expired_amount_total` | Counter | – | 만료 소멸 금액 합 |
| `wallet_lot_expiry_backlog` | Gauge | – | 상한에 걸려 남은 묶음 수 (조용한 절단 방지) |
| `wallet_lot_expiry_skipped_locked_total` | Counter | – | SKIP LOCKED로 건너뛴 수 |
| `wallet_reconcile_mismatch_pairs` | Gauge | – | 마지막 대사에서 어긋난 (wallet, store) 수 |
| `wallet_reconcile_last_run_epoch_seconds` | Gauge | – | 마지막 대사 완료 시각 |

**Slack·이메일 등 외부 알림은 만들지 않는다.** 관측은 로그 + 위 메트릭이 전부다. (Micrometer + Prometheus + Grafana는 이미 붙어 있다.)

## C-6. 로그 규약 (grep 가능해야 한다)

```
log.warn("[LEDGER_MISMATCH] cause={} walletId={} storeId={} balance={} lotSum={} diff={}", ...)
log.info("[LOT_EXPIRY] walletId={} storeId={} lots={} amount={} deducted={}", ...)
log.warn("[LOT_EXPIRY_BACKLOG] remaining={} limit={}", ...)
log.info("[RECONCILE] scanned={} mismatch={} over={} under={} elapsedMs={}", ...)
```

- `[LEDGER_MISMATCH]`는 **반드시 WARN 이상.** 부하테스트 후 `grep '\[LEDGER_MISMATCH\]'` 한 줄로 판정 가능해야 한다.
- 로그에 개인정보(고객명, 전화번호)를 넣지 않는다. ID만.

## C-7. 설정 프로퍼티 (platform-agent 소유)

```yaml
wallet:
  expiry:
    lazy-enabled: true            # 결제 임계 경로에서 즉시 만료 정산
    batch-size: 500               # 한 번에 조회할 후보 lot 수
    max-groups-per-run: 200       # 1주기당 처리할 (wallet, store) 묶음 상한
    cron: "0 10 3 * * *"          # 매일 03:10 KST
  capture:
    strict-lot: false             # true면 lotLeft != 0 시 롤백. 3단계 전환용. 기본 false
  reconcile:
    cron: "0 40 3 * * *"          # 매일 03:40 KST (만료 배치 30분 뒤)
    page-size: 1000
```

- `@ConfigurationProperties(prefix = "wallet")` 로 `WalletLedgerProperties` 하나에 묶는다.
- 모든 프로퍼티는 `application.yml`에 기본값을 두고 `application-prod.yml`에서 필요 시 덮는다.
- `zone = "Asia/Seoul"` 을 `@Scheduled`에 명시한다 (`SettlementScheduler` 기존 패턴과 동일).

## C-8. ErrorCode (platform-agent가 한 번에 추가. 다른 도메인AI는 추가하지 않는다)

| 추가/재사용 | 코드 | HTTP | 메시지 | 쓰는 곳 |
|---|---|---|---|---|
| **신규** | `REFUND_ORIGINAL_TX_REQUIRED` | 400 | `환불 요청에 원거래 ID가 필요합니다.` | `processRefund` |
| 재사용 | `FUNDS_INVARIANT_VIOLATION` | 500 | (기존) | lot 복원 상한 초과, `strict-lot` 롤백 |
| 재사용 | `INCONSISTENT_STATE` | 409 | (기존) | – |
| 재사용 | `PAYMENT_IN_PROGRESS` | 409 | (기존) | 락 타임아웃 |

**새 에러 코드가 더 필요하면 만들지 말고 오케스트레이션AI에게 보고한다.** `ErrorCode` enum은 충돌이 잦은 파일이라 한 에이전트만 건드린다.

## C-9. 운영 엔드포인트 (internal-agent 소유, wallet 서비스 호출)

| 메서드 | 경로 | 인증 | 반환 |
|---|---|---|---|
| POST | `/internal/ops/lot-expiry/run` | `X-Internal-Auth` | `ApiResponse<ExpirySweepReport>` |
| POST | `/internal/ops/reconcile/run` | `X-Internal-Auth` | `ApiResponse<ReconcileReport>` |

- 인프라 담당이 부하테스트 직후 정합성을 판정하는 도구다. 스케줄 대기 없이 즉시 돌릴 수 있어야 한다.
- `/internal/*` 이므로 Nginx가 외부 차단하고 `validateInternalAuth`로 한 번 더 검증한다 (기존 컨트롤러 패턴 그대로).
- 이 경로는 **작업 3(monolith `/internal` 자원 격리)의 대상에 포함**되므로 네임스페이스를 `/internal/ops/*`로 고정한다.

## C-11. 전 도메인 공통 금지 사항

1. **착수 전 "완료 조건 = 통과해야 할 테스트 목록"을 워크로그에 먼저 적는다.** `backend/CLAUDE.md` 워크플로우 요구다. 원래는 사람 승인을 받지만 **무인 모드에서는 사람을 기다리지 않는다** — 목록을 워크로그에 남기고 바로 진행하라. 사람이 돌아와서 목록과 결과를 대조한다.
2. **잔액 소유권을 qr-service로 옮기자는 제안을 하지 않는다.** 검토했고 기각했다 (설계안 §6, `docs/v2/구조검토_잔액소유권과_격리.md`).
3. **`wallet_store_balances` 테이블을 없애자는 제안을 하지 않는다.** 기각 근거는 조회 성능이 아니라 balance 행이 결제의 직렬화 앵커라는 점이다.
4. **Slack·이메일·외부 알림을 만들지 않는다.** 로그 + 메트릭이 전부다.
5. **다른 도메인AI의 파일을 건드리지 않는다.** 필요하면 오케스트레이션AI에게 요청한다.
6. **`ErrorCode` enum은 platform-agent만 건드린다.**
7. **`keeping.sql`과 DDL은 schema-agent만 건드린다.**
8. **과장하지 않는다.** 이 프로젝트 문서의 미덕은 정직함이다 — "처리량은 개선되지 않았다, 가치는 안정성이다"처럼 한계를 그대로 적어왔다. 측정하지 않은 것을 "빨라졌다"고 쓰지 않는다.
9. **줄바꿈·포맷 노이즈를 만들지 마라.** 커밋을 쪼갤 수 없는 무인 모드에서는 포맷 변경이 그대로 기능 diff에 섞인다. **네가 실제로 고치는 줄만 건드려라.** 파일 전체 재포맷 금지.
10. **`./gradlew test`를 돌리지 않는다.** 테스트는 작성만 하고, 실행 명령은 `복귀체크리스트.md`에 적는다.
11. **워크로그(`docs/v2/worklog/<세트번호>_<에이전트>.md`)를 반드시 남긴다.** 이게 없으면 사람이 변경을 리뷰할 수 없다.
