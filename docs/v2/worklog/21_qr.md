## 5. Q-6: refundForRecovery originalTransactionId 페이로드 검증

### 분석

`PaymentRecoveryService.performExternalRecovery()` (line 163-169):
```java
RefundRequest refundRequest = RefundRequest.builder()
    .walletId(intent.getWalletId())
    .storeId(intent.getStoreId())
    .amount(intent.getAmount())
    .originalTransactionId(checkResult.getTransactionId())  // ← 여기서 채움
    .reason("UNCERTAIN 상태 자동 복구")
    .build();
```

`originalTransactionId`는 `checkPaymentForRecovery()` 응답의 `transactionId`에서 가져온다.
- `exists==false`이면 환불 자체를 건너뛰므로 문제 없음 (line 155-158)
- `exists==true`이면 항상 `checkResult.getTransactionId()`를 넣음
- **단, `exists==true && transactionId==null`인 비정상 응답에 대한 방어 로직은 없음** -- monolith PR #20에서 필수화하면 이 경우 monolith가 400으로 거부할 것

### 작성한 테스트

`PaymentRecoveryServiceTest`에 2건 추가:
1. `refundForRecovery_항상_originalTransactionId를_포함한다` -- 정상 경로, captor로 값 일치 검증
2. `refundForRecovery_checkResult의_transactionId가_null이면_그대로_전달된다` -- null 전파 확인 (monolith 필수화 근거)
