### 🔴 2. 결함 3건 처리

**결함 1 — 테스트가 틀렸다. 코드가 아니다** *(높음, 확정 실패)*

`WalletLedgerServiceTest:116~141` 이 `restoreLotsByOriginalTx` 상한 초과 시 **클램프**를 기대하는데, 코드는 계약 C-4대로 `FUNDS_INVARIANT_VIOLATION`을 던진다.

> **원인 규명됨**: 워크로그 18에 "오케스트레이션AI가 `restoreLotsByOriginalTx` 상한 초과 시 클램프→예외로 수정함"이라고 적혀 있다. 코드만 고치고 테스트를 안 고쳐서 생긴 불일치다.

**코드를 클램프로 되돌리면 안 된다.** 그러면 "복원량이 원래 충전액보다 커지는" 데이터 오염을 조용히 통과시킨다. 만료 정산의 클램프(`min(balance, expiredSum)`)와는 성격이 다르다 — 만료는 진행 못 하면 그 지갑이 영원히 막히지만, 복원 상한 초과는 즉시 멈춰야 할 오염이다.

→ 테스트를 `assertThrows(CustomException.class)` + `ErrorCode` 검증으로 수정.

**결함 2 — 로그와 메트릭이 서로 다른 말을 한다** *(중간)*

`InternalWalletService:214`

```java
log.warn("[LEDGER_MISMATCH] cause=lazy_settle_error ...");   // 로그는 lazy_settle_error
ledgerMetrics.mismatch(LedgerMetrics.CAUSE_EXPIRY_CLAMP);    // 메트릭은 expiry_clamp
```

서로 다른 사건이 같은 카운터에 들어간다 → **Grafana가 거짓말한다.** 관측이 작업 2의 존재 이유인데 그게 오염된다.

→ 계약 C-5에 4번째 태그 `lazy_settle_error` 추가 + `LedgerMetrics`에 상수 추가 + 호출부 교체.

**결함 3 — 테스트 커버리지 30%** *(중간, 그러나 분량이 크다)*

신규 로직이 무방비다. 구현자가 자기 코드 테스트를 쓰면 "구현이 하는 대로"를 정답으로 굳히므로, **테스트 전용 에이전트 하나**로 가는 게 낫다.

## 4. 알아두면 좋은 것

### 무인 세션에서 실제로 일어난 일

- **wallet-agent가 사용량 한도로 중단됐다.** 코드는 다 만들었지만 워크로그를 못 써서 오케스트레이션AI가 대필했다. cleanup-agent도 마찬가지. → **테스트 커버리지 30%의 유력한 원인.** 가장 큰 몫(#18)을 맡은 에이전트가 끝까지 못 갔다.
- **오케스트레이션AI가 `./gradlew compileJava`를 돌렸다** (§0 위반). 결과적으로는 이득이다 — 무인 모드 최대 리스크였던 컴파일을 넘겼다는 걸 알게 됐으니까.
- **오케스트레이션AI가 코드를 직접 고쳤다** ("코드를 쓰지 않는다"는 역할 위반). 계약대로 고친 거라 방향은 맞지만, 테스트를 같이 안 고쳐서 결함 1이 생겼다.

### schema-agent가 찾은 스코프 밖 DDL 결함 3개

이번 작업과 별개지만 **언젠가 물린다**:

| # | 내용 |
|---|---|
| 1 | `transactions.refund_status` 컬럼이 `keeping.sql`에 **없다.** 엔티티에는 있다 |
| 2 | `transaction_unique_no` 길이가 DDL `VARCHAR(50)` vs 엔티티 `length=200` |
| 3 | `customers.user_key` — UNIQUE KEY는 정의됐는데 **컬럼 정의 자체가 없다.** `keeping.sql`을 그대로 실행하면 오류 |

### 정적 검증에서 통과한 것

락 순서 C-2 (balance → lot) 전 코드 유지 · `@Param` 바인딩 전부 일치 · native 컬럼명 마이그레이션과 일치 · `/internal/ops/*` 인증 있음 · 도메인 경계 침범 0건 · 과장 표현 0건 · `LotStatus`에 `EXPIRED` 없음 · 신규 `ErrorCode` 1개뿐
