### G-3: push path 정상 플로우

```bash
# 터미널 A: 손님이 QR 발급 후 롱폴링
# 1) QR 발급
QR_RES=$(curl -s -X POST \
  -H "Authorization: Bearer <CUSTOMER_JWT>" \
  -H "Content-Type: application/json" \
  -d '{"walletId":1,"bindStoreId":1}' \
  http://localhost:8081/api/qr)
TOKEN_ID=$(echo $QR_RES | jq -r '.data.tokenId')

# 2) 롱폴링 등록 (백그라운드)
curl -s \
  -H "Authorization: Bearer <CUSTOMER_JWT>" \
  http://localhost:8081/api/qr/$TOKEN_ID/intent &
POLL_PID=$!

# 터미널 B: 점주가 스캔 → initiate
SESSION_RES=$(curl -s -X POST \
  -H "Authorization: Bearer <OWNER_JWT>" \
  http://localhost:8081/api/qr/$TOKEN_ID/scan)
SESSION_TOKEN=$(echo $SESSION_RES | jq -r '.data.sessionToken')

curl -s -X POST \
  -H "Authorization: Bearer <OWNER_JWT>" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"storeId":1,"items":[{"menuId":1,"quantity":1}]}' \
  http://localhost:8081/cpqr/$SESSION_TOKEN/initiate

# → 터미널 A의 curl이 200 OK + IntentArrivalResponse 반환 확인
wait $POLL_PID
```

**기대 로그 (qr-service)**:
```
[INTENT_WAIT] 등록 — tokenId=xxx customerId=xxx
[QR_FLOW] intent 도착 — tokenId=xxx intentPublicId=xxx
[INTENT_WAIT] 해소(push) — tokenId=xxx intentPublicId=xxx
```

### G-4: poll path (initiate-first 엣지케이스)

initiate 가 먼저 완료된 뒤 손님이 롱폴링을 시작하는 케이스.

```bash
# 1) scan → initiate 먼저 실행
# 2) 그 다음 손님이 롱폴링
curl -s \
  -H "Authorization: Bearer <CUSTOMER_JWT>" \
  http://localhost:8081/api/qr/$TOKEN_ID/intent
# → 즉시(200 ms 이내) 200 OK 반환 (register 직후 Redis GET으로 즉시 해소)
```

**기대 로그**:
```
[INTENT_WAIT] 등록 직후 즉시 해소 — tokenId=xxx
[INTENT_WAIT] 해소(poll) — tokenId=xxx intentPublicId=xxx
```

## 롤백 기준

| 상황 | 조치 |
|---|---|
| `GET /{tokenId}/intent` 가 항상 204 반환 | Redis `qrflow:intent:*` 키 확인. AFTER_COMMIT 리스너 로그 누락이면 `initiate` TX 문제. |
| `GET /{tokenId}/intent` 가 즉시 500 | `IntentWaitRegistry` 빈 초기화 로그 확인. `intentWaitScheduler` Bean 누락 여부. |
| 손님 응답 지연 (~2 ms 초과 현저) | `QrFlowIntentReadyListener`의 동기 실행 코스트 측정. Redis WRITE_THROUGH 모드 확인. |
| `notification_dropped_total` 급증 | `notification.executor.core-size` / `max-size` 값 환경 변수로 상향. |
