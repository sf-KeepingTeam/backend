# #63 컨트롤러 — GET /{tokenId}/intent 엔드포인트 (2026-09-01)

## 신규 파일

### `domain/intent/dto/IntentArrivalResponse` (record)

```java
record IntentArrivalResponse(
    String intentPublicId,
    Long amount,
    String storeName,
    List<PaymentIntentItemView> items
)
```

## 수정 파일

### `domain/qr/controller/QrController`

추가 의존성: `QrFlowRedisStore`, `IntentWaitRegistry`
(`@RequiredArgsConstructor` 로 자동 주입)

신규 엔드포인트: `GET /api/qr/{tokenId}/intent`

**응답 코드 정의**:

| 상황 | 응답 |
|---|---|
| active 키 없음 (스캔 전·만료) | 404 Not Found |
| customerId 불일치 | 403 Forbidden (registry 에서 처리) |
| initiate 완료 (25 s 이내) | 200 OK + IntentArrivalResponse |
| 25 s 타임아웃 | 204 No Content (클라이언트 재시도) |

**DeferredResult 설정**:
```java
new DeferredResult<>(25_000L, ResponseEntity.noContent().build())
```
timeout-result 를 생성자에 넣어 Spring이 타임아웃 시 자동 처리.

**인증**: `@AuthenticationPrincipal UserPrincipal` — customerId(principal.id()) 추출.
SecurityConfig 별도 수정 불필요: 기존 `/api/qr/**` 인증 설정이 이 경로를 포함.

## 주의사항

- `GET /api/qr/{tokenId}` (기존) 와 `GET /api/qr/{tokenId}/intent` (신규) 는 경로 충돌 없음.
  전자는 `/{tokenId}`, 후자는 `/{tokenId}/intent` — Spring MVC 가 구체적 경로 우선.
- DeferredResult 는 Spring MVC 기본 지원 — 의존성 추가 0.
- 기존 async dispatcher 설정(application.yml) 별도 수정 불필요.
