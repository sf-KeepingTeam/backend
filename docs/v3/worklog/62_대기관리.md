# #62 대기 관리 — IntentWaitRegistry + intentWaitScheduler (2026-09-01)

## 신규 파일

### `domain/intent/service/IntentWaitRegistry`

**waiter 자료구조**: `ConcurrentHashMap<String, WaiterEntry>`
- key: tokenId
- value: `WaiterEntry(DeferredResult, expectedCustomerId)` (내부 record)

**두 가지 해소 경로**:

| 경로 | 트리거 | DB 조회 | StoreClient |
|---|---|---|---|
| push | `QrFlowIntentReadyListener.resolve()` | ✗ (이벤트가 items 포함) | ✓ (캐시 우선) |
| poll | 200 ms 스케줄러 MGET | ✓ (intent + items) | ✓ (캐시 우선) |

**onCompletion 핸들러**: `waiters.remove(tokenId) + activeWaiterCount.decrementAndGet()`
→ timeout / error / 정상 해소 모두 자동 정리.

**poll 루프**:
1. `new ArrayList<>(waiters.keySet())` 스냅샷
2. `QrFlowRedisStore.mgetIntentArrival(tokenIds)` — Redis MGET 1회
3. non-null 값 파싱: `split(":", 2)` → UUID + customerId
4. `resolveFromDb(tokenId, intentPublicId, customerId)` 호출

**동시성**: push + poll 모두 `DeferredResult.setResult()` 호출 가능.
Spring 내부 AtomicBoolean으로 두 번째 호출은 false 반환 후 무시.

### `AsyncConfig.intentWaitScheduler` Bean

```java
Executors.newScheduledThreadPool(2, daemonThreadFactory("intent-wait-"))
```
기존 `@Scheduled` 1 스레드(Spring 기본, 복구 스케줄러 점유)와 완전 분리.
데몬 스레드: JVM 종료 시 폴러가 블로킹하지 않음.

## 지표

| 이름 | 종류 | 설명 |
|---|---|---|
| `intent_wait_registered_total` | Counter | 롱폴링 요청 등록 수 |
| `intent_wait_resolved_total` | Counter | 정상 해소 수 (push + poll) |
| `intent_wait_timeout_total` | Counter | 25 s 타임아웃 수 |
| `intent_wait_active` | Gauge | 현재 대기 중 waiter 수 |

## 검증 게이트 (수동)

- Prometheus: `intent_wait_registered_total`, `intent_wait_resolved_total` 증가 확인
- Gauge `intent_wait_active` — 롱폴링 1개 열면 1, 완료 후 0
