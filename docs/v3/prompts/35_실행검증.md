## 0. 이번엔 실행한다 — 앞선 세트와 정반대다

세트 #30~#34는 **"빌드·테스트·서버 접근 전면 금지"** 로 돌았다. 사람이 자는 동안 권한 승인을
할 수 없었기 때문이다. 그 결과:

**코드는 전부 작성됐지만 한 번도 컴파일·테스트·실행되지 않았다.**

이번 세트는 **사람이 옆에 있다.** 그래서 정반대다 — **실행이 네 임무의 전부다.**

| 이번엔 허용 | 이번에도 금지 |
|---|---|
| `./gradlew build` / `test` | **EC2·프로덕션 DB 접근** — 인프라 담당 영역 |
| `docker` (Testcontainers·로컬 MySQL/Redis) | **k6 부하측정** — 인프라 담당 영역 |
| 로컬 서버 기동 + `curl` 스모크 | **성능 수치 주장** — 측정은 인프라가 한다 |
| 로컬 DB 마이그레이션 적용 | **`git push`** — 커밋까지만. 푸시는 사람이 |
| 테스트 실패 시 **코드 수정** | 새 기능 추가. 이번은 **"돌아가게 만들기"** 뿐 |

### ★ 사람의 승인을 아껴 써라

사람이 계속 붙어 있지 못한다. **권한 승인이 필요한 명령을 흩뿌리지 마라.**

- **§2를 먼저 통째로 돌려라.** 승인이 몰려 있어야 사람이 한 번에 처리하고 자리를 뜰 수 있다
- 한 명령으로 묶을 수 있으면 묶어라 (`(cd monolith && ./gradlew clean build test)`)
- **`gradlew test` 는 Docker(Testcontainers)를 깨운다.** Docker Desktop이 떠 있는지 **먼저 확인하고**,
  안 떠 있으면 사람에게 그것부터 요청하라
- 승인 대기로 막히면 **그 항목만 건너뛰고 다음으로** 가라. 전체를 멈추지 마라

### 페이저·에디터에 갇히지 마라

`git` 은 항상 `--no-pager`. `git commit` 은 반드시 `-m`. `git log`/`diff` 는 `| cat` 또는 `--no-pager`.
`tail -f`·`watch`·포그라운드 서버는 금지 — 서버는 백그라운드로 띄우고 로그는 파일로 받아라.

## 2. 1단계 — 컴파일과 테스트 (승인이 몰리는 구간. 먼저 돌려라)

### 2-1. 사전 확인

```bash
docker info > /dev/null 2>&1 && echo "Docker OK" || echo "Docker 꺼짐 — 사람에게 요청"
```

Docker가 꺼져 있으면 **사람에게 Docker Desktop 실행을 요청**하고, 그동안 §2-2(컴파일)만 진행하라.

### 2-2. 컴파일

```bash
(cd monolith && ./gradlew clean compileJava compileTestJava -x test)
(cd qr-service && ./gradlew clean compileJava compileTestJava -x test)
```

**실패하면 §1-4의 의심 지점부터 보라.** 고쳐라 — 이번엔 수정이 허용된다.

### 2-3. 테스트

```bash
(cd monolith && ./gradlew test)
(cd qr-service && ./gradlew test)
```

**`spotlessJava` 와 `generateContractTests` 태스크 순서 충돌**이 기존 이슈로 보고돼 있다
(`build` 태스크에서만 발생, 컴파일은 정상). **이번 변경과 무관하므로 고치려 들지 마라** —
`test` 만 돌려서 우회하고, 막히면 워크로그에 적고 넘어가라.

### 2-4. 실패를 다루는 원칙

| 실패 유형 | 대응 |
|---|---|
| **컴파일 에러** | 고쳐라. 계약(`docs/v3/오케스트레이션.md` §4)을 지키면서 |
| **테스트 실패 — 테스트가 틀림** | 테스트를 고쳐라. **단, 코드가 계약대로면 테스트가 틀린 것이다** |
| **테스트 실패 — 코드가 틀림** | 코드를 고쳐라 |
| **어느 쪽이 틀렸는지 애매** | **계약 문서가 정답이다.** `오케스트레이션.md` §4 / `docs/v2/prompts/00_공유계약.md` 를 근거로 판단하고 워크로그에 근거를 남겨라 |
| **기존(v2·v3 이전) 테스트 실패** | **회귀다. 크게 보고하라.** 이번 변경이 깨뜨린 것일 수 있다 |

> ⚠️ **테스트를 지우거나 `@Disabled` 로 덮어서 초록불을 만들지 마라.**
> 그건 검증을 없애는 것이지 통과시키는 게 아니다. 못 고치겠으면 **실패한 채로 두고 보고**하라.

## 3. 2단계 — 로컬 스모크 (진짜 돌아가는지)

테스트가 초록불이어도 **애플리케이션이 뜨는지, 결제가 되는지는 별개다.**

### 3-1. 스키마 준비

v2가 만든 마이그레이션이 로컬 DB에 적용됐는지 확인하고, 안 됐으면 적용하라.

```bash
# 적용 여부 확인
mysql -u root -p<PW> keeping -e "SHOW COLUMNS FROM wallet_store_lot LIKE 'expired%';"

# 없으면 적용
mysql -u root -p<PW> keeping < mysql/migration/V2025_08_21__lot_expiry_columns.sql

# 조사 스크립트도 이 참에 (읽기 전용)
mysql -u root -p<PW> keeping < mysql/ops/v2_스키마조사.sql
```

**`v2_스키마조사.sql` 결과를 워크로그에 그대로 붙여라.** v2 내내 "확인 불가"였던 세 가지가 여기서 풀린다:

- `transactions.transaction_type` ENUM에 `REFUND` 가 실제로 있는가
- `transactions.customer_id` 가 실제로 `NOT NULL` 인가
- CHECK 제약이 실효성 있는가 (MySQL 8.0.16+)
- **존량 불일치 건수** ← `strict-lot` 전환 판단의 근거

### 3-2. 기동

`local` 프로필로 백그라운드 기동. **포그라운드로 띄우면 세션이 물린다.**

```bash
(cd monolith   && nohup ./gradlew bootRun > /tmp/monolith.log 2>&1 &)
(cd qr-service && nohup ./gradlew bootRun > /tmp/qr.log 2>&1 &)
# 뜰 때까지 대기 후
curl -s localhost:8080/actuator/health
curl -s localhost:8081/actuator/health
```

**`ddl-auto`** 를 확인하라. `local` 은 `update` 라 컬럼이 자동 생성될 수 있는데,
**그러면 §3-1의 마이그레이션 검증이 무의미해진다.** 마이그레이션을 먼저 적용하고 기동하라.

### 3-3. 🔴 D-1 검증 — 이게 이번 세트의 핵심

**결제 승인 알림이 실제로 발송되는지 확인하라.**

```
운영 기본값 그대로: async=true, split-transaction=true, token-enabled=true
결제 4단계를 태운다:
  1) POST /api/qr                     → 201
  2) POST /api/qr/{tokenId}/scan      → 200   (v2 #27에서 고친 직렬화 버그 회귀 확인)
  3) POST /cpqr/{session}/initiate    → 201
  4) POST /payments/{intentId}/approve → 200
```

**그리고 monolith 로그와 DB를 확인하라:**

```bash
grep "PAYMENT_APPROVED" /tmp/monolith.log
mysql -u root -p<PW> keeping -e "SELECT id, type, created_at FROM notifications ORDER BY id DESC LIMIT 5;"
```

| 결과 | 의미 |
|---|---|
| 알림이 **있다** | D-1 수정(`fallbackExecution=true`)이 먹었다. ✅ |
| 알림이 **없다** | **D-1이 살아 있다. 최우선으로 고쳐라.** 운영 기본값에서 승인 알림 100% 유실 |

**플래그를 끄고도 확인하라** — `async=false` 로 두면 알림이 나가는가? 그럼 비동기 경로만의 문제다.

### 3-4. 나머지 스모크

| # | 확인 | 기대 |
|---|---|---|
| S-1 | 결제 4단계 (§3-3) | 전부 2xx |
| S-2 | `POST /internal/ops/reconcile/run` (`X-Internal-Auth` 포함) | `ReconcileReport` 반환. **불일치 건수를 기록하라** |
| S-3 | `POST /internal/ops/lot-expiry/run` | `ExpirySweepReport` 반환 |
| S-4 | 위 둘을 **헤더 없이** | 401 |
| S-5 | `curl localhost:8080/actuator/prometheus \| grep wallet_` | v2 메트릭 7개. **Gauge가 `NaN` 이 아닌지** |
| S-6 | PIN 토큰 발급 → 그 토큰으로 approve | 200. `verifyPin` 호출 로그가 **없어야** 한다 |
| S-7 | **다른 intent용 토큰**으로 approve | **거부** ← 보안상 가장 중요 |
| S-8 | 같은 토큰 2회 | 두 번째 거부 (jti 재사용 차단) |
| S-9 | `token-enabled=false` + PIN | 기존 경로로 200 (병행 지원 확인) |
| S-10 | `grep '\[LEDGER_MISMATCH\]' /tmp/*.log` | 클린 DB 기준 **0건** |
| S-11 | `grep '\[APPROVE_PHASE\]' /tmp/qr.log` | 구간별 로그가 실제로 찍히는가 |

**S-7이 실패하면 배포하면 안 된다.** 남의 주문서를 결제할 수 있다는 뜻이다.

### 3-5. 하지 않는 것

- **성능 수치를 재지 마라.** 로컬은 조건이 다르고, 측정은 인프라 담당이 EC2에서 한다
- `/actuator/health` 응답시간을 로컬에서 재고 "개선됐다"고 쓰지 마라. **무부하 로컬은 원래 빠르다**
- Hikari 커넥션 지표를 로컬에서 판정하지 마라

## 4. 3단계 — 커밋


### 4-1. ⚠️ `git add .` 을 하지 마라

작업 트리에 **이번 작업과 무관한 미커밋 변경이 섞여 있다** (v2 때 확인됨):

| 섞여 있는 것 | 정체 |
|---|---|
| `docs/archive/**` 삭제 + `docs/v1/archive/` 신규 | 이전 세션의 v1 동결 작업 |

| `qr-service/docs/`, `monolith/data_erd.md` | 이전부터 있던 untracked |

**경로를 명시해서 `add` 하라.** 커밋은 세트 단위로 쪼개면 좋지만, 이미 섞여 있으면

3. **`git push` 하지 마라.** 커밋까지만. 푸시는 사람이 판단한다
4. **EC2·프로덕션 DB에 접근하지 마라.** 인프라 영역이다
5. **k6 부하측정을 시도하지 마라.** 인프라 영역이다

10. **`git commit` 을 `-m` 없이 하지 마라.** 에디터가 열려 세션이 물린다
11. **실패를 숨기지 마라.** 인프라가 모르고 측정하면 그 측정이 통째로 버려진다
