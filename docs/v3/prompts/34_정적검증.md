## ⛔ 0. 절대 제약 — 코드 작성만 한다 (다른 모든 지시보다 우선)

| 금지 | |
|---|---|
| **빌드 실행** | **네가** `gradlew`·`docker build`·`docker compose` 를 부르는 것 금지 (훅이 자동으로 도는 건 예외 — 바로 아래 참조) |
| **테스트 실행** | 단위·통합·컨트랙트 **돌리지 마라.** Testcontainers가 Docker를 깨워 세션이 멎는다 |
| **서버 접근** | EC2, k6, Prometheus, DB 접속 금지 |
| **측정** | 성능 검증을 시도하지 마라 |
| **`git` 쓰기** | 커밋·브랜치·푸시 금지. `.git/` 수정은 권한 프롬프트를 띄운다 |

**검증은 인프라 담당이 재측정으로 한다.** 너는 **파일 편집만** 하고 끝낸다.
테스트 *코드*를 새로 쓰는 것은 괜찮다 — **실행하지만 마라.**

허용: 저장소 안 파일 읽기/쓰기, `grep` `rg` `find` `cat` `sed` `wc`,
`git --no-pager log/blame/diff/status` (읽기 전용).

**멈추지 마라.** 사람에게 질문하고 기다리지 마라. 판단이 갈리면 **가장 안전한 쪽으로 쓰고
그 가정을 워크로그에 명시**하라. 확인할 수 없는 것은 "확인 불가"로 적고 넘어가라.

**컴파일을 못 돌린다.** 그래서 반드시:
- 참조하는 클래스·메서드는 **실제 파일을 열어 시그니처를 확인**하고 쓴다. 기억으로 쓰지 마라
- `import` 를 빠짐없이, 정확한 패키지 경로로
- 새로 만든 필드·메서드를 쓰는 쪽과 만드는 쪽이 **같은 이름**인지 저장 직전에 재대조
- `@RequiredArgsConstructor` 에 의존하는 주입은 `private final` 선언을 빠뜨리지 않는다


### ⚠️ 훅이 자동으로 컴파일한다 — 네가 한 게 아니다

이 저장소에는 **`PostToolUse` 훅**이 걸려 있다 (`.claude/settings.json`, `.claude/settings.local.json`).
**`.java` 파일을 편집할 때마다 훅이 자동으로 `./gradlew compileJava` 를 돌린다.**

```
.claude/hooks/post-edit.sh    .java 편집 시 해당 모듈 compileJava (timeout 90s, 실패 시 exit 1)
.claude/hooks/smoke-build.sh  같은 일 (항상 exit 0)
.claude/hooks/check-env.sh    .env / application*.yml 저장 시 필수 변수 경고
```

**그래서 이런 출력이 보인다:**

```
🔨 [qr-service] Java 파일 변경 감지 → 컴파일 체크 중...
✅ [qr-service] 컴파일 성공
```

**이건 네가 빌드를 실행한 게 아니다. 훅이 한 것이고 §0 위반이 아니다.**

| 해야 할 것 | 하지 말 것 |
|---|---|
| 훅이 **컴파일 실패**를 뱉으면 **즉시 고쳐라.** 이게 이번 작업의 유일한 컴파일 안전망이다 | 훅이 돌았다고 해서 **너도 `./gradlew` 를 직접 불러도 된다고 착각하지 마라** |
| 훅 출력을 워크로그에 "훅 컴파일 결과"로 인용해도 된다 | **`./gradlew test` 는 절대 금지.** 훅은 `compileJava` 만 돌린다. 테스트는 Testcontainers(Docker)를 깨워서 세션이 멎는다 |
| 편집 후 훅 출력을 **반드시 확인하고 넘어가라** | 훅 결과를 "테스트 통과"로 부풀리지 마라. **컴파일과 테스트는 다르다** |

**훅 때문에 편집 하나마다 수 초가 붙는다.** 조급해하지 말고, 대신 **불필요한 재편집을 줄여라** —
한 파일을 여러 번 찔끔찔끔 고치지 말고 한 번에 제대로 써라.

## 1. 배경 — 왜 이걸 고치나 (30초)

Keeping은 선결제 포인트 결제 플랫폼이다. monolith(8080) + qr-service(8081), 별도 DB·Redis,
REST + Webhook(`X-Internal-Auth`) 통신.

부하측정으로 확정된 것:

| | 구성 1 (합침) | 구성 2 (분리) |
|---|---|---|
| 조회 부하 500 하 결제 성공률 | 31.7% | **99.1%** |
| approve p95 | 7,700 ms | **6,687 ms** |

**서버 분리는 "붕괴"는 막았으나 "지연"은 못 막았다.** SLO(1,000 ms)의 6.7배다.

**병목은 MySQL이다** — Hikari 풀을 20→60으로 3배 늘렸는데 처리량이 **−3.2%** 였고
CPU는 평균 42%로 여유였다. 커넥션이 부족했던 게 아니라 **커넥션 뒤의 MySQL이 한계**였다.

그래서 방향은 둘뿐이다: **쓰기를 줄인다 / 커넥션 점유 시간을 줄인다.**

상세 근거·수치: `docs/v3/요청_코드개선_측정근거.md`
전체 측정 기록: `docs/측정결과_부하격리/result.md`

## 2. 공유 계약 (임의 변경 금지 — 원본은 `docs/v3/오케스트레이션.md` §4)

### V-1. 설정 키

```yaml
payment:
  notification:
    async: true
  approve:
    split-transaction: true
  pin:
    token-enabled: true
    token-ttl-seconds: 60
```

`@ConfigurationProperties(prefix = "payment")` 로 **`PaymentTuningProperties` 하나**에 묶는다.
`@Value` 를 흩뿌리지 마라. **세트 #30이 이 클래스를 만들고 #31·#33이 필드를 추가한다.**

**플래그를 두는 이유**: 인프라 원칙이 "한 번에 하나만 바꾼다"인데 개선이 3건이다.
플래그가 있으면 **배포는 한 번, 측정은 조건별로** 할 수 있고,
개선이 오히려 악화시키면 **코드 롤백 없이 플래그 한 줄로 되돌린다.**
기본값은 전부 `true`.

### V-2. `PaymentStatus` enum 을 건드리지 않는다

새 중간 상태(`PROCESSING`/`AUTHORIZING` 등)를 **추가하지 마라.**
DB ENUM 컬럼이라 마이그레이션이 따라오고, **복구 스케줄러가 이미 오래된 `PENDING` 을
스윕하므로 필요가 없다.**

### V-3. 트랜잭션 경계 규약

```
[TX-A]  멱등 슬롯 선점 · intent 검증 · items 스냅샷 로드     → 커밋
[NO-TX] PIN 검증 (HTTP) · 자금 캡처 (HTTP)                  ← 커넥션 안 쥔다
[TX-B]  intent 재조회 · 상태 전이 · 멱등 complete            → 커밋
[AFTER] 알림
```

1. **`[NO-TX]` 구간에서 어떤 리포지토리도 호출하지 마라.** 하나라도 부르면 커넥션을 다시 쥔다
2. **TX-B는 intent를 재조회한다** — `PaymentIntent` 에 `@Version` 낙관적 락이 있다
3. **TX-A/TX-B는 별도 빈의 `REQUIRES_NEW`** — self-invocation은 프록시를 우회한다
4. **`IntentStatusUpdater` 패턴을 따르라.** 이미 있는 것을 새로 만들지 마라

### V-4. 관측 — 인프라가 재측정 판정에 쓴다. 바꾸지 마라

| 지표 | 기대 |
|---|---|
| `hikaricp_connections_active{qr}` 최대 | 15 → **15 미만** |
| `hikaricp_connections_pending{qr}` 최대 | 12 → **0** |
| `/actuator/health` | 424 ms → **수십 ms** ← **가장 명확한 지표** |

```
log.info("[APPROVE_PHASE] phase={} intentId={} elapsedMs={}", ...)
log.warn("[APPROVE_ORPHAN] intentId={} reason={}", ...)
```

### V-5. 하지 말아야 할 것 (측정으로 배제됨)

| | 이유 |
|---|---|
| **Argon2 파라미터 약화** | OWASP 1순위. 알고리즘 선택은 옳다. 측정용 도구였고 원복됐다 |
| **Hikari 풀만 키우기** | 20→60 실험에서 처리량 **−3.2%**. 병목이 아니다 |
| **톰캣 스레드만 키우기** | 200 포화는 원인이 아니라 결과다 |
| **캐싱 확대** | HTTP 호출은 없애도 같은 MySQL·CPU 경합은 못 막는다 |
| **PIN 잠금 정책 완화** | PIN은 6자리라 경우의 수가 10⁶. 실질 1차 방어선은 해시가 아니라 잠금이다 |

### V-6. 산출물 3종 (전부 파일)

1. 코드·테스트 파일 수정 (테스트는 **작성만**)
2. `docs/v3/worklog/<세트번호>_<이름>.md`
3. `docs/v3/worklog/인프라_인계.md` 에 **append** — 인프라가 재측정 전에 알아야 할 것
   (플래그 기본값·배포 순서 제약·새 설정·관측 지점). **부실하면 재측정이 막힌다**

## 3. 네 역할 — 적대적으로 읽는다

너는 **검증 담당**이고 **코드 수정 권한이 없다.** 앞선 4개 세트가 만든 것을 **의심하는 것**이 일이다.

**할 수 있는 것**: 모든 코드·워크로그 읽기, 보고서 파일 쓰기(`docs/v3/worklog/34_검증.md`),
`인프라_인계.md` 보강

**할 수 없는 것**: 프로덕션 코드 수정, 테스트 코드 수정, 다른 에이전트의 워크로그 수정

**이 경계가 중요한 이유**: 검증자가 코드를 고치기 시작하면 자기 코드를 자기가 검증하게 된다.
그 순간 검증의 의미가 사라진다.

**실행이 금지돼 있으므로 "통과했습니다"라고 쓸 수 있는 항목이 하나도 없다.**
있다면 네가 금지된 명령을 실행했거나 거짓말을 한 것이다.

## 4. 검증 항목

### 4-1. 금지 명령 실행 흔적 (이걸 먼저)

- 워크로그에 "BUILD SUCCESSFUL", "테스트 통과", "응답 확인", "측정 결과" 같은 표현 → **위반**
- `git --no-pager log --oneline -10` — 이 작업 중 새 커밋이 생겼는가 → **위반**
- `git --no-pager status` — `build/`, `.gradle/` 같은 빌드 산출물이 생겼는가 → **위반**

### 4-2. 세트별 완료 기준 대조

| 세트 | 확인할 것 |
|---|---|
| **#30** | `approve()`·`initiate()` 본문에 `notificationClient` 직접 호출 **0건**. 이벤트에 JPA 엔티티 없음. 전용 스레드풀 + **큐 포화 시 버리는 정책**(`CallerRunsPolicy` 면 ❌) |
| **#31** | HTTP 호출을 감싸는 `@Transactional` 없음. **`[NO-TX]` 구간 리포지토리 호출 0건**. TX-B가 재조회. 별도 빈 `REQUIRES_NEW`(self-invocation ❌) |
| **#32** | 토큰에 **intentPublicId + jti + exp**. Argon2 파라미터 무변경. **잠금 정책 살아 있음**. 기존 `pin-verify` 살아 있음 |
| **#33** | 토큰 경로에 `verifyPin` 호출 0건. **intentPublicId 대조 있음**. `jti` Redis 기록. `verifyPin` 삭제 안 됨 |

### 4-3. ★ `[NO-TX]` 구간 무결성 — 이번 v3의 핵심이다

세트 #31의 성과 전체가 여기에 걸려 있다. **직접 grep해서 증명하라.**

```bash
# approve 경로에서 트랜잭션 밖 구간을 찾아 그 안의 호출을 전수 확인
grep -n "Repository\.\|repository\." qr-service/src/main/java/.../PaymentIntentService.java
```

`[NO-TX]` 구간에 **JPA 리포지토리 호출이 하나라도 있으면 커넥션을 다시 쥔다.**
`/actuator/health` 424 ms가 그대로 남는다는 뜻이고, **이번 작업 전체가 헛수고가 된다.**

예외: `FundsService` 내부의 `IntentStatusUpdater`(UNCERTAIN 마킹)는 `REQUIRES_NEW` 라
잠깐 커넥션을 쥔다. **예외 경로라 빈도가 낮으니 허용**이지만, 워크로그에 명시됐는지 확인하라.

### 4-4. 컴파일 위험 정적 점검 — 네가 컴파일러 역할이다

| # | 점검 |
|---|---|
| K-1 | `PaymentTuningProperties` 정의(#30)와 사용부(#31·#33)의 **getter 이름 일치** |
| K-2 | **세트 #32가 넣는 클레임 이름/타입 == 세트 #33이 읽는 것.** 워크로그 두 개를 나란히 놓고 대조 |
| K-3 | 새로 만든 이벤트/DTO의 필드명이 발행부·수신부에서 일치 |
| K-4 | `import` 누락 (`@TransactionalEventListener`, `TransactionPhase`, `Propagation` 등) |
| K-5 | `@RequiredArgsConstructor` 클래스의 주입 대상이 `private final` 로 선언됨 |
| K-6 | `application.yml` 의 `payment.*` 키가 `@ConfigurationProperties` 구조와 정확히 대응 |
| K-7 | 삭제된 심볼의 잔존 참조 |

**K-2가 가장 위험하다.** monolith와 qr이 다른 세트라 계약이 어긋나면 **컴파일은 통과하고
런타임에 토큰 검증이 전부 실패**한다. 클레임 이름을 글자 단위로 대조하라.

### 4-5. 껍데기 테스트 색출

실행할 수 없으니 **코드를 읽어서** 판정한다.

| 냄새 | |
|---|---|
| 단언이 없다 | `assert`/`verify`/`assertThat` 이 한 줄도 없음 |
| 자명한 단언 | `assertTrue(true)`, `assertNotNull(service)` 만 |
| 호출만 하고 결과를 안 본다 | 예외만 안 나면 통과 |
| 대상을 안 짚는다 | K-2("다른 intent용 토큰 거부")인데 정상 토큰만 넣는다 |
| `@Disabled`/`@Ignore` | 꺼둔 테스트 |

**이 테스트들이 실제로 무언가를 지키는지 확인하라:**

| 테스트 | 지켜야 할 것 |
|---|---|
| N-2 | 알림 실패해도 **결제가 성립**함을 단언하는가 |
| T-2 | PIN 실패 시 **DECLINED가 DB에 남는지** 단언하는가 (롤백 버그 회귀 방어) |
| T-5 | 예외 주입 후 **복구 대상 쿼리가 그 intent를 실제로 반환**하는지 단언하는가 ("예외가 났다"만 보면 무의미) |
| K-2 | **다른 intent용 토큰이 거부**되는지 단언하는가 |
| K-5 | **같은 토큰 2회째가 거부**되는지 단언하는가 |

### 4-6. 논리 추적 — 코드를 읽고 시나리오를 머리로 돌려라

| 시나리오 | 확인 |
|---|---|
| 정상 결제 | TX-A → HTTP → TX-B → 알림 순서가 코드로 성립하는가 |
| TX-A 후 프로세스 사망 | intent가 PENDING, 멱등 IN_PROGRESS. **복구 쿼리 조건에 실제로 걸리는가** |
| capture 성공 후 TX-B 실패 | **돈은 빠졌는데 상태가 안 남는다.** 어떻게 되는가 — 이게 가장 위험한 경로다 |
| 같은 멱등키 동시 2회 | 1회만 처리되는가 |
| 토큰 검증 실패 | 세트 #31의 상태 전이와 일관되는가 |

**세 번째가 제일 중요하다.** 트랜잭션을 쪼개면 새로 생기는 위험이고,
복구 스케줄러가 커버한다는 게 설계의 전제였다. **코드로 그게 성립하는지 확인하라.**

### 4-7. 과장 색출

이 프로젝트 문서의 미덕은 정직함이다.

- 측정 없이 "빨라졌다 / 개선되었다 / 커넥션 점유가 줄었다"
- **실행하지 않고 "확인했다 / 통과했다"**
- "monolith 의존이 사라졌습니다" (자금 캡처가 남아 있다)
- 인프라 문서 §5의 한계 — **"셋을 다 해도 SLO 1,000 ms 는 미달일 가능성이 높다"** — 가 슬그머니 사라졌는지

## 6. 하지 말 것

1. **코드를 고치지 마라.** 결함은 보고한다
2. **테스트를 고치지 마라.** 부족하면 부족하다고 보고한다
3. **"통과했습니다"를 쓰지 마라.** 실행할 수 없다. 쓸 수 있는 건 "정적으로 확인함" 뿐
4. **§4-3(`[NO-TX]` 무결성)과 §4-4 K-2(클레임 계약)를 건너뛰지 마라.** 다른 걸 다 해도 이 둘을 안 하면 실패다
5. **확인하지 못한 것을 "이상 없음"으로 쓰지 마라**
6. **애매한 걸 ✅로 내리지 마라.** 애매하면 ⚠️
7. **결함을 "사소하니 넘어가자"고 판단하지 마라.** 심각도를 붙여 전부 올려라
8. **`gradlew`·`docker`·`git` 쓰기를 실행하지 마라**
